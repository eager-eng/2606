# 问题二计算结果

## 求解概况

以第 0-2399 小时实际到达任务和第 0-2406 小时逐时电力参数为输入，采用带候选时空剪枝的启发式调度。运行成本、碳排放和新能源利用率构成基准归一化三目标函数；网络时延作为任务级硬约束、候选位置次级选择规则和最终服务质量评价指标。附件给出的购电、售电、弃电和储能轨迹作为基准状态，仅根据优化 AI 负荷相对基准 AI 负荷的变化进行边际能源结算。当两者相等时，计算结果严格恢复附件基准指标。

共处理 50,000 条任务，成功调度 50,000 条，计算耗时 311.69 s。

## 核心结果

- 净运行成本由 1,801,660,137.89 CNY 变为 1,579,315,537.38 CNY，相对变化 -12.34%。
- 碳排放由 2,045,367.48 tCO2 变为 1,844,591.71 tCO2，相对变化 -9.82%。
- 新能源利用率由 32.86% 提升至 36.56%，提高 3.70 个百分点。
- 以任务均在来源区域执行作为本地参考，其平均网络时延为 5.00 ms；问题二方案平均时延为 28.27 ms，P95 时延为 78.00 ms，最大时延为 82.00 ms。
- 任务迁移率为 76.12%，三目标综合值为 -0.111361。

优化后的净运行成本保持为正，成本、碳排放和新能源利用率均按附件原始基准结果进行比较。电力平衡残差来自附件逐时数据的小数位舍入，采用 0.001 MW 作为通过阈值。

- 任务遗漏或未排程：通过，违约数或残差为 0
- 任务重复排程：通过，违约数或残差为 0
- 任务早于允许时刻开工：通过，违约数或残差为 0
- 任务连续执行时长不一致：通过，违约数或残差为 0
- 实时任务未立即开工：通过，违约数或残差为 0
- 网络时延超限：通过，违约数或残差为 0
- 任务截止时间或2406超限：通过，违约数或残差为 0
- GPU容量超限：通过，违约数或残差为 0
- IT功率超限：通过，违约数或残差为 0
- 设施功率超限：通过，违约数或残差为 0
- 电力平衡最大残差_MW：通过，违约数或残差为 0.000200417

## 成果文件

- `任务调度方案.csv`：每条任务的执行区域、开工和完工时刻、网络时延及迁移标记。
- `区域逐时负荷与能源.csv`：各区域逐时 GPU、IT、设施负荷与购售电、弃电和碳排放结果。
- `指标对比.csv`：基准方案与问题二方案的成本、碳排放、新能源利用率和网络时延。
- `约束检验.csv`：任务、容量、时延、截止时刻和电力平衡检验。
